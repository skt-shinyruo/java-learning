# I/O 基础：同步、异步、阻塞、非阻塞

这四个词经常一起出现，但它们不是同一组维度。

| 概念 | 关注点 | 核心问题 |
| --- | --- | --- |
| 同步 / 异步 | 调用者怎么拿结果 | 是自己等结果，还是之后被通知？ |
| 阻塞 / 非阻塞 | 等待时线程会不会卡住 | 线程是否停在那里不能继续执行？ |

一句话先记住：

> 同步 / 异步说的是“结果怎么回来”；阻塞 / 非阻塞说的是“线程会不会等到卡住”。

## 1. 同步和异步

**同步**：发起调用后，调用者要自己等到结果，或者自己主动去查结果。

```java
String result = query();
System.out.println(result);
```

这里 `query()` 不完成，后面的代码就不能拿到结果。

**异步**：发起调用后，调用者不直接等结果，结果将来通过回调、事件、`Future`、`Promise`、消息等方式回来。

```java
queryAsync(result -> {
    System.out.println(result);
});
```

调用发出去后，当前流程可以继续走，结果以后再处理。

## 2. 阻塞和非阻塞

**阻塞**：调用时如果条件不满足，当前线程会被挂起，卡在那里。

```java
int n = inputStream.read(buffer);
```

如果没有数据，`read()` 可能一直等，当前线程不能继续执行后面的业务代码。

**非阻塞**：调用时如果条件不满足，立刻返回，不让线程卡住。

```java
int n = channel.read(buffer);
if (n == 0) {
    // 没数据，先去做别的
}
```

非阻塞调用不代表结果已经有了。它只是说：如果现在做不了，就先返回一个状态，让调用者决定接下来轮询、注册事件，还是处理别的任务。

## 3. 四种组合

同步 / 异步与阻塞 / 非阻塞可以组合在一起。

| 组合 | 解释 | 例子 |
| --- | --- | --- |
| 同步阻塞 | 自己等结果，并且线程卡住 | 普通阻塞 I/O、同步 RPC |
| 同步非阻塞 | 自己查结果，但没结果就立刻返回 | 非阻塞 socket + 轮询 |
| 异步阻塞 | 结果异步产生，但调用方又阻塞等待 | 提交任务后立刻调用 `Future.get()` |
| 异步非阻塞 | 发起后立即返回，结果好了再通知 | 回调、事件循环、`CompletableFuture` 回调 |

最容易混淆的是“同步非阻塞”和“异步非阻塞”。

同步非阻塞里，调用者仍然要自己主动问：

```text
有数据吗？没有。
有数据吗？没有。
有数据吗？有，开始读。
```

异步非阻塞里，调用者通常先注册好处理逻辑，然后等系统或框架通知：

```text
数据好了，回调你注册的处理逻辑。
```

## 4. 一个排队类比

可以用排队办业务来理解。

- 同步：你在窗口前等结果。
- 异步：你取号后先去做别的，轮到你再通知你。
- 阻塞：你人被卡在原地，不能做别的。
- 非阻塞：这次没办成也先让你走，你可以稍后再来或等通知。

所以：

- 同步阻塞：站在窗口前一直等。
- 同步非阻塞：反复去窗口问“好了吗”，没好就先走开。
- 异步阻塞：取号后本来可以离开，但你又坐在原地死等叫号。
- 异步非阻塞：取号后去做别的，叫到号再回来处理。

## 5. Java 语境下的一个注意点

日常说“线程被阻塞”是泛称，意思是线程因为等待 I/O、锁、条件、时间等原因不能继续执行当前逻辑。

但 `Thread.State.BLOCKED` 是 Java 线程状态里的一个具体状态，主要表示线程正在等待进入 `synchronized` 关联的 monitor 锁。很多“阻塞式等待”在 Java 线程状态里可能表现为 `WAITING`、`TIMED_WAITING`，甚至在底层 I/O 等待时仍显示为 `RUNNABLE`。

因此讨论 I/O 模型时，不要把“阻塞调用”和 `Thread.State.BLOCKED` 简单画等号。
